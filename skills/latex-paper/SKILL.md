# LaTeX Research Paper Skill

Standardize the authoring, formatting, provenance tracking, and compilation of academic research papers written in LaTeX.

This skill defaults to a clean, modern double-column conference/arXiv preprint template, enforces experiment lineage tracking for all figures and tables, and provides dual-target compilation to both PDF and Word (`.docx`).

---

## 1. Directory Structure

All paper assets reside inside the `paper/` directory:

```text
paper/
├── .gitignore               # Ignores auxiliary files (.aux, .bbl, .log, etc.)
├── Makefile                 # Automation recipes for PDF, DOCX, and verification
├── main.tex                 # Entry point: documentclass, packages, \input sections
├── macros.tex               # Notation definitions, math operators, draft comments
├── references.bib           # Consolidated BibTeX bibliography
├── runs.json                # Experiment lineage manifest mapping runs to artifacts
├── scripts/
│   └── sync_runs.py         # Provenance tool to import and verify run artifacts
├── figures/                 # Vector PDFs and raster images generated by runs
├── tables/                  # Modular table snippets (\input{tables/...})
└── sections/                # Modular paper sections
    ├── 00_abstract.tex
    ├── 01_introduction.tex
    ├── 02_related_work.tex
    ├── 03_methodology.tex
    ├── 04_experiments.tex
    ├── 05_results.tex
    └── 06_conclusion.tex
```

Starter templates for all of these files are located in `templates/` within this skill.

## 2. Prerequisites & Missing Tools Policy

> [!IMPORTANT]
> **Agent Policy**: Do not install missing system packages or tools on your own. Never run commands with elevated permissions (such as `sudo apt`, `brew install`, or system package managers).
>
> When any required tool is missing:
> 1. Stop the build or export task immediately.
> 2. Inform the user which specific tool is missing.
> 3. Suggest the appropriate installation command so the user can install it themselves.

### Tool Verification & Installation Commands

Verify tool availability with `command -v <tool>` before running build commands:

| Tool | Purpose | Ubuntu / Debian | macOS (Homebrew) | Arch Linux | Fedora |
|---|---|---|---|---|---|
| `latexmk` | Multi-pass PDF build | `sudo apt install latexmk texlive-latex-extra` | `brew install --cask mactex-no-gui` | `sudo pacman -S texlive-bin texlive-latexextra` | `sudo dnf install latexmk texlive-scheme-medium` |
| `pdflatex` | Base LaTeX compiler | `sudo apt install texlive-latex-base` | (Included in MacTeX / BasicTeX) | `sudo pacman -S texlive-basic` | `sudo dnf install texlive-latex` |
| `pandoc` | Export to Word (`.docx`) | `sudo apt install pandoc` | `brew install pandoc` | `sudo pacman -S pandoc-cli` | `sudo dnf install pandoc` |

*(Note: `sync_runs.py` relies exclusively on Python 3's built-in standard library with `json`, requiring zero external Python packages).*

When notifying the user, use this clear format:
> "The required tool `pandoc` is not installed on your system. Please install it to enable Word (.docx) export:
> ```bash
> sudo apt install pandoc
> ```"

## 3. Compilation & Export Workflow

### Building PDF (`latexmk`)
Use `latexmk` for automated multi-pass compilation. It resolves references, citations, and auxiliary files automatically.

```bash
# Compile paper to PDF
make pdf
# Or invoke latexmk directly:
latexmk -pdf -synctex=1 -interaction=nonstopmode main.tex

# Continuous compilation watch mode during writing
make watch
```

### Exporting to Word (`.docx`) via `pandoc`
When submitting to venues, co-authors, or reviewers that require Word documents, export the LaTeX source to `.docx` using `pandoc` with citation processing:

```bash
# Export to build/main.docx
make docx
# Or invoke pandoc directly:
mkdir -p build
pandoc main.tex \
    --from latex \
    --to docx \
    --output build/main.docx \
    --bibliography=references.bib \
    --citeproc \
    --standalone
```

#### Best Practices for Clean `.docx` Conversion
1. Keep modular sections included via `\input{sections/...}`. Pandoc parses `\input` statements automatically.
2. Store custom mathematical operators in `macros.tex` using standard LaTeX `\newcommand` or `\DeclareMathOperator`.
3. Use standard `\cite{...}` keys present in `references.bib`. Pandoc `--citeproc` formats citations according to the chosen style.
4. Avoid nested, non-standard TeX conditional loops in prose text.

## 4. Experiment Run Lineage (`runs.json`)

Never copy plots or tables manually into `paper/` without recording their origin. A paper must track exactly which experiment run, code commit, and dataset produced each figure and table.

### The Manifest (`paper/runs.json`)
`runs.json` records metadata, source folders, git commits, and SHA256 checksums for all imported assets:

```json
{
  "runs": {
    "baseline_resnet50": {
      "description": "Baseline training run on standard benchmark split",
      "source_dir": "experiments/runs/2026-10-20_resnet50_baseline",
      "imported_at": "2026-10-26T08:00:00Z",
      "git_commit": "a1b2c3d4e5",
      "artifacts": [
        {
          "path": "figures/loss_convergence.pdf",
          "source_file": "experiments/runs/2026-10-20_resnet50_baseline/plots/loss.pdf",
          "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
          "imported_at": "2026-10-26T08:00:00Z"
        }
      ]
    }
  }
}
```

### Managing Runs with `sync_runs.py`

The skill provides the `sync_runs.py` utility in `scripts/sync_runs.py` (written using only Python standard library `json`).

#### 1. Import Run Artifacts
Copy figures or tables from an experiment directory and log them into `runs.json`:

```bash
# Import a figure from an experiment run
python3 scripts/sync_runs.py import \
    --run-id exp_transformer_v2 \
    --source ../experiments/outputs/exp_v2/ \
    --files loss_curve.pdf attention_map.pdf \
    --category figures \
    --notes "Trained with cosine learning rate schedule for 100 epochs" \
    --commit 7f3b89a

# Import a table
python3 scripts/sync_runs.py import \
    --run-id exp_transformer_v2 \
    --source ../experiments/outputs/exp_v2/ \
    --files ablation_table.tex \
    --category tables \
    --notes "Main ablation results table"
```

#### 2. List Active Paper Runs
View all experiment runs contributing to the current draft:

```bash
python3 scripts/sync_runs.py list
```

#### 3. Verify Artifact Integrity
Verify that every figure and table in `paper/figures/` and `paper/tables/` matches its recorded checksum in `runs.json`:

```bash
make verify
# Or run directly:
python3 scripts/sync_runs.py verify
```

The script alerts you if:
- A file exists on disk but lacks an entry in `runs.json` (untracked artifact).
- A file was modified on disk after import (checksum mismatch).
- A file is listed in `runs.json` but is missing from disk.

## 5. Academic Typography & Style Standards

### Full-Width Abstract and Keywords
In two-column layouts, the title, abstract, and keywords must span the full page width across both columns before starting the two-column body flow. Wrap `\maketitle` and `\input{sections/00_abstract}` inside `\twocolumn[\begin{@twocolumnfalse} ... \end{@twocolumnfalse}]` in `main.tex`:

```latex
\begin{document}

\twocolumn[
  \begin{@twocolumnfalse}
    \maketitle
    \input{sections/00_abstract}
    \vspace{1.5em}
  \end{@twocolumnfalse}
]

\input{sections/01_introduction}
```

Include `\begin{abstract}...\end{abstract}` followed by `\noindent \textbf{Keywords:} ...` in `sections/00_abstract.tex`.

### Sectioning & Modularization
- Keep `main.tex` minimal. It should only contain preamble settings, metadata, and `\input{sections/...}` statements.
- Write each major section in a separate file inside `sections/`.
- Name section files with numeric prefixes (`01_introduction.tex`, `02_related_work.tex`) to preserve reading order.

### Quotation Marks
- Never use straight double quotes (`"word"`).
- Always use LaTeX directional quotes:
  ```latex
  ``quoted phrase''
  `single quote'
  ```

### Non-Breaking Spaces (Ties)
Always place a non-breaking space (`~`) before citations and cross-references to avoid awkward line breaks:
- `Figure~\ref{fig:architecture}`
- `Table~\ref{tab:ablation}`
- `Section~\ref{sec:methodology}`
- `Equation~\eqref{eq:loss}`
- `Vaswani et al.~\cite{vaswani2017attention}`

### Tables
- Strictly prohibit vertical lines (`|`).
- Use the `booktabs` package (`\toprule`, `\midrule`, `\bottomrule`).
- Always place the table caption **above** the table.
- Center numeric columns and align decimal points where appropriate.

```latex
\begin{table}[t]
    \centering
    \caption{Classification accuracy across benchmark datasets. Best results in bold.}
    \label{tab:results}
    \begin{tabular}{lccc}
        \toprule
        Model & Dataset A & Dataset B & Latency (ms) \\
        \midrule
        Baseline & 82.4 & 76.1 & 14.2 \\
        Ours     & \textbf{87.9} & \textbf{81.3} & \textbf{11.8} \\
        \bottomrule
    \end{tabular}
\end{table}
```

### Figures
- Always place the figure caption **below** the figure.
- Prefer vector formats (`.pdf`) over raster images (`.png`, `.jpg`) for plots, charts, and diagrams.
- Reference all figures in the main text before or on the page where they appear.

```latex
\begin{figure}[t]
    \centering
    \includegraphics[width=\linewidth]{figures/loss_convergence.pdf}
    \caption{Training loss convergence across 100 epochs. Shaded regions denote standard deviation.}
    \label{fig:convergence}
\end{figure}
```

### Mathematics & Display Equations
- Never use obsolete `$$...$$` syntax.
- Use `equation` for numbered single equations, or `align` from `amsmath` for multi-line equations.
- Include punctuation (commas, periods) at the end of display equations when they terminate or separate clauses in a sentence.
- Define reusable math symbols and operators in `macros.tex`.

## 6. Collaboration & Review

Use `macros.tex` for inline draft feedback:

```latex
\todo{Verify baseline numbers with rerun}
\note{Add citation to newer 2026 benchmark}
```

Toggle off all draft annotations for camera-ready compilation by switching `\draftfalse` in `macros.tex`:

```latex
\newif\ifdraft
\draftfalse % Suppresses all \todo and \note blocks
```

## 7. Pre-Submission Checklist

- [ ] Run `make verify` to ensure all figures and tables match recorded runs in `runs.json`.
- [ ] Run `make pdf` and verify zero compilation errors or missing citations (`?` or `[?]`).
- [ ] Check for unreferenced figures or tables.
- [ ] Verify that all cross-references use non-breaking spaces (`Figure~\ref{...}`).
- [ ] Ensure all tables use `booktabs` with captions on top.
- [ ] Verify that `\draftfalse` is set in `macros.tex` for final submission.
- [ ] If required by co-authors or submission portal, run `make docx` to generate the Word document.
